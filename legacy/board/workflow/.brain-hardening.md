# Brain hardening — first-live-wake audit (2026-07-25)

Auditor pass over brain/{BRAIN.md,brain.js,act.js,state.js,run-brain.sh,gate.js} + the live
first-wake brain.log. Every claim below was verified against the live system tonight.

## Root causes found (evidence first)

1. **The brain was flying blind on names and prices — this caused BOTH observed hazards.**
   `state.js` reads names/prices from `/api/v3/market-ticker/0/` captured off the store page,
   but that capture reliably comes back EMPTY: the live `brain/.state.json` (re-verified with a
   fresh capture at 01:02Z, rc=0) has every stock name as `k2/k5/k7/...` and every
   `keyPrices` value `null`. With no names and no prices in its state, the model *guessed*
   `coffee-ground`, then `coffee powder`, and *guessed* `price:0`. The price collector already
   captures the full 142-product ticker every 2 minutes into
   `price-tracker/data/{names.json,prices.jsonl}` — reuse it (fix F4), and guard anyway (F1).
2. **Name trap is real and two-sided**: the game's exchange name for kind 119 is
   `"coffee ground"` (names.json) while the retail sell card is `"COFFEE POWDER"`. Two name
   spaces, one product. (F1 canonicalizer + F7 doc.)
3. **`sell price:0` reached the browser** and only the game's own disabled SELL button
   ("Too low") saved 84 powder from a $0 listing. No guard exists anywhere in our code. (F1)
4. **`buy` param footgun, observed live**: the model called
   `buy {"kind":"seeds","maxSpend":10000,"ask":true}`. It only failed because the URL
   `/market/resource/seeds/` isn't a market page. Had `kind` been numeric, `buy.js` line 18
   (`const ask = askHint || ...`) would have used `ask=true` as the unit price → 
   `qty = floor(10000/true) = 10000 UNITS` bought at whatever the book asked. (F2)
5. **Stale-alarm refire loop (design bug, not yet observed)**: nothing ever consumes
   `next-wake.json`. Both safety nets — brain.js finish handler
   (`if (!fs.existsSync(next-wake.json))`) and run-brain.sh line 26 (`[ -f ... ] ||`) — test
   *existence*, but a stale already-due file from the previous wake ALWAYS exists. So any wake
   that ends without `set_alarm` (crash, `timeout 900` kill, model forgets) leaves a past-due
   alarm → gate.js refires the FULL brain every 2 minutes: browser churn + OpenAI spend +
   **repeated real actions**, all night. (F5 — one `mv` fixes both nets.)
6. **Produce wage-prepay gap**: `act.js` passes `minCashAfter` into `window.__produce`, but
   `pages/produce.js` destructures only `{name, qty, preset}` — minCashAfter is silently
   ignored. Wages are charged up front and forfeited on cancel (the $8,136 Mill lesson), so a
   large-qty order with inputs on hand can crater cash below the floor with no guard. (F3)

## Checked and already fine (no change)

- **Produce inputs-on-hand guard**: `pages/produce.js` L38-49 already refuses when inputs are
  short — never clicks BUY MISSING, bails if PRODUCE is absent/disabled, warehouse untouched.
  No duplicate guard needed in act.js; the model's beans-1000 order was correctly accepted.
- **LESSONS rule 1 (cdp.close + exit)**: act.js and state.js both end with
  `cdp.close(); process.exit(0)` and error paths exit(1). Wake 1's mysterious 160s state
  timeout (log 19:49→19:51:41, exactly the `timeout 160`) predates the current state.js — the
  file's mtime is 19:53, i.e. it was hot-fixed right before wake 2. Verified tonight: one live
  `timeout 160 flock -w 90 .tick.lock node brain/state.js` run = **48s, rc=0, clean exit**.
- **Locks**: act.js does navigate+act in ONE cdp session under one flock (B5 respected);
  brain.js wraps act/state in `flock -w 90` with sane timeouts; pure-fetch is not over-locked.
- **Cron**: collector and gate both on `1-59/2` (odd minutes) exactly per spec; gate itself
  touches no browser and .tick.lock serializes the rest.
- **Key hygiene**: usage.jsonl holds only token counts; the key is never logged. (F6 tightens
  env scoping as defense-in-depth.)
- **Alarm clamp** (10 min–4 h) in brain.js matches BRAIN.md; wake-2's alarm landed correctly
  at 01:30:53Z (5 min before the farm order finishes).
