Target: `tick.js` (deterministic fast loop). Source of truth: `board/.realizable.json`
(written by `realizable.js`), `DOCTRINE.md` (Rule 1, 4d, 5b, 6), `config.json`.

**Finding:** `tick.js` references `board/.realizable.json` **zero times**. As a result the
deterministic loop keeps choosing `OVERSUPPLIED` output (grapes, kind 5) to *produce* on the
farm and to *sell* through the single store lane, converting cash into frozen inventory instead

behaviour* whenever the JSON is missing or stale.

## 1. Degradation contract (must hold — this is a live money loop)

The metric is **advisory and fail-open**. Every guard below returns "not de-prioritised" when the
data is absent, malformed, or stale, so the loop falls back to *current* behaviour and never crashes:

- File missing / unreadable / bad JSON → `loadRealizable()` catches → `{fresh:false}`.
- `generated` older than `maxAgeHours` (default 12h) or unparseable → `{fresh:false}`.
- `!fresh` → `deprioKind()` returns `false` for every kind → sorts/branches behave as they do today.
- Unknown kind → `false`.
- The metric is used **only to reorder / branch among options config already allows**. It never
  invents a product, never changes what to build/pivot (strategist's job), never sells surplus, and
  never leaves a building idle: an OVERSUPPLIED good is *sunk in priority*, not removed, so it still
  wins the lane when nothing sellable is in stock (Rule 6).
- Rule 1 preserved: among sellable goods the store's own `Profit per hour` probe still ranks the
  fine choice; the metric only decides the coarse tier.

## DIFF 0 — loader + guard helper, and one line to expose it on `state`

**Where:** insert the two helpers at top level right after `rateFor()` (currently ends line 64).
Both are `function` declarations, so hoisting makes call-order irrelevant; they depend only on
`fs`, `path`, `DIR`, `CFG` (all defined by line 19).

```js
// --- realizable-demand guard (board/.realizable.json, written by realizable.js) -----------------
// Classifies every product by how much of its output the market can ACTUALLY absorb (DOCTRINE
// Rule 4d). The fast loop uses it ONLY to DE-PRIORITISE OVERSUPPLIED/MIRAGE goods among the options
// config already allows — never to change strategy. FAIL-OPEN: missing/stale/bad data => no effect.
function loadRealizable() {
  try {
    const j = JSON.parse(fs.readFileSync(path.join(DIR, 'board', '.realizable.json'), 'utf8'));
    const ageMs = Date.now() - Date.parse(j.generated || 0);          // NaN if timestamp missing/bad
    const staleMs = ((CFG.realizable || {}).maxAgeHours || 12) * 3600e3;
    if (!j.byKind || !(ageMs < staleMs)) return { byKind: {}, fresh: false }; // absent/old -> fail open
    return { byKind: j.byKind, fresh: true, generated: j.generated };
  } catch (e) { return { byKind: {}, fresh: false }; }                 // absent/malformed -> fail open
}
// True only when FRESH data marks the kind as unsellable-into (OVERSUPPLIED or any MIRAGE*). Unknown
// kinds and stale/missing data -> false, so the loop keeps its current behaviour untouched.
function deprioKind(realizable, kind) {
  if (!realizable || !realizable.fresh) return false;
  const v = realizable.byKind[String(kind)];
  return !!v && (v.verdict === 'OVERSUPPLIED' || String(v.verdict).startsWith('MIRAGE'));
}
```

**Where:** `readState()` return object (currently line 192, `buildings, stock, price, retailAvg, mods,`).
Attaching it to `state` is the whole wiring: `pickStoreOrder(state)`, `pickFarmOrder(state)`, the
farm block and the surplus block all already receive `state`, so no signature changes anywhere.

```js
    buildings, stock, price, retailAvg, mods,
    realizable: loadRealizable(),        // <-- add: advisory demand verdicts, fail-open
```

Load cost: one small local `fs.readFileSync` once per tick. Deterministic, bounded, no model.

## DIFF 1 — `pickStoreOrder`: sink OVERSUPPLIED goods below the sales lane's real earners

**Where:** the final priority sort, currently lines 296–302.
**Symptom fixed:** #2 — grapes ($287/h) taking the single store lane between powder bursts while
steak (RETAIL-OK $334/h) and sausages (RETAIL-OK $379/h) pile as frozen inventory.

**Before:**
```js
  const prio = CFG.storePriority || {};
  results.sort((a, b) => {
    const pa = prio[a.kind] ?? 99, pb = prio[b.kind] ?? 99;
    if (pa !== pb) return pa - pb;          // priority tier first
    return b.score - a.score;               // then $/h within the tier
  });
  return results[0] || null;
```

**After:**
```js
  const prio = CFG.storePriority || {};
  // Realizable de-prioritisation (Rule 4d): an OVERSUPPLIED good (grapes, market absorbs ~19/h) must
  // not hold the SINGLE sales lane ahead of a RETAIL-OK good (powder/steak/sausages). +1000 sinks it
  // a whole tier below everything sellable, so it only wins the lane when nothing sellable is in
  // stock — never a hard skip (Rule 6, store never idle). The $/h probe still ranks WITHIN each tier
  // (Rule 1). Fail-open: stale/missing data -> tier == old prio -> identical behaviour.
  const tier = (c) => (prio[c.kind] ?? 99) + (deprioKind(state.realizable, c.kind) ? 1000 : 0);

    if (ta !== tb) return ta - tb;          // priority tier first (OVERSUPPLIED sunk +1000)
    return b.score - a.score;               // then $/h within the tier (game's Profit-per-hour probe)
```

live $/h probe) → grapes (1099, last resort). `candidates` is already stock-gated, so `results[0]`
is always the best *in-stock* good and is never null unless the store truly holds nothing sellable.

## DIFF 2 — `pickFarmOrder`: prefer an absorbable crop, but never return null

**Where:** function body, currently lines 314–328.
**Symptom fixed:** #1 (partial) — makes the crop ranker refuse to *prefer* an OVERSUPPLIED fruit
over a non-oversupplied one, while structurally guaranteeing it still returns a crop (callers do
`pickFarmOrder(state).name` / `.kind`, so returning null would crash the farm block — never idle).

**Before:**
```js
function pickFarmOrder(state) {
  let best = null;
  for (const c of CFG.farmProducts) {
    const matCost = c.inputs.reduce((sum, [kind, mult]) => {
      const unit = state.stock[kind]?.unitCost ?? state.price[kind] ?? 0;
      return sum + unit * mult;
    }, 0);
    const realRate = c.baseRate * (state.accel?.multiplier ?? CFG.accelerationFactor ?? 1);
    const cost = matCost + CFG.farmWage / realRate;
    const profit = c.retailNet - cost;
    const score = MODE === 'xp' ? c.retailAvg * c.storeRate : profit * c.storeRate;
    if (!best || score > best.score) best = { ...c, cost, profit, score };
  }
  return best;
}
```

**After:**
```js
function pickFarmOrder(state) {
  let best = null, bestOk = null;   // bestOk = best crop the market can still absorb
  for (const c of CFG.farmProducts) {
    const matCost = c.inputs.reduce((sum, [kind, mult]) => {
      const unit = state.stock[kind]?.unitCost ?? state.price[kind] ?? 0;
      return sum + unit * mult;
    }, 0);
    const realRate = c.baseRate * (state.accel?.multiplier ?? CFG.accelerationFactor ?? 1);
    const cost = matCost + CFG.farmWage / realRate;
    const profit = c.retailNet - cost;
    const score = MODE === 'xp' ? c.retailAvg * c.storeRate : profit * c.storeRate;
    const cand = { ...c, cost, profit, score };
    if (!best || score > best.score) best = cand;
    if (!deprioKind(state.realizable, c.kind) && (!bestOk || score > bestOk.score)) bestOk = cand;
  }
  // Prefer a crop the market can absorb; if EVERY farm crop is OVERSUPPLIED/MIRAGE, still return the
  // best of them (never null -> caller never crashes, farm never idles, Rule 6). The real alternative
  // to all-oversupplied fruit — grow beans for the Mill — is handled by the caller (see DIFF 3).
  // Fail-open: stale/missing data -> bestOk === best -> unchanged behaviour.
  return bestOk || best;
}
```

Note: with *today's* data all three fruit are OVERSUPPLIED, so `bestOk` stays null and this returns
the same fruit as before — correct. DIFF 2 only bites the day one fruit is oversupplied and another
is not. The grape→beans switch that fixes the measured pile lives in DIFF 3.

## Scope guard — what this integration deliberately does NOT do

- Does **not** decide which industry to build/pivot to — that stays with the strategist/board. It
  only reorders/branches among crops and store products config already lists.
- Does **not** scale B2B-DEEP / B2B-THIN / B2B-BLIND by rate, and does **not** trust `bookStale:true`
  magnitudes. It reads only the categorical `verdict`, and acts only on OVERSUPPLIED/MIRAGE.
- Does **not** sell surplus, touch the Beach market, add Catering, change the $500/$2,500/$5,000
  reserves, or make any model call. Fully deterministic and bounded.
- Never idles a building: every guard is a de-prioritisation with a guaranteed non-null fallback
  (store sells the oversupplied good if it's all that's in stock; farm grows beans, else the best
  fruit, else seeds).

## Residuals to hand to the strategist (not fast-loop fixes)

1. **Bean overflow tail.** When the Mill is *not* hungry (bean buffer already ≥6h) and all fruit is
   OVERSUPPLIED, DIFF 3 keeps growing beans past the buffer. Beans are B2B-DEEP (fraction 0.5,
   drainable) and have intrinsic Mill use, so this is strictly better than piling OVERSUPPLIED fruit —
   but it is unbounded. Consider a `surplusWatch` entry for coffee-beans (118) and/or a bean-buffer
   cap in config so the strategist is woken if beans themselves start piling.
2. **Root cause is structural, not fast-loop.** Three RETAIL-OK finished goods (powder, steak,
   sausages) contend for ONE store sales lane; the metric confirms the farm's fruit output has almost
   no home. A second retail outlet / dedicated powder outlet, or dropping fruit from `farmProducts`
   entirely, is a strategist decision — flagged here, not taken.
3. Re-run `node realizable.js` after each `board-data.json` refresh (DOCTRINE Rule 4d) so the verdicts
   the fast loop now reads stay current; otherwise the 12h staleness gate fails the loop open.
