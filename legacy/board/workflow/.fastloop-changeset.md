# Fast-loop change-set — tick.js (+ config.json)

Author: fast-loop change architect · 2026-07-24 · synthesized from `.fastloop-audit-decisions.md`,
`.fastloop-audit-metric.md`, `.fastloop-audit-robust.md`, verified against live `tick.js`,
`config.json`, and `board/.realizable.json`.

## Guardrails honoured

- `tick.js` stays DETERMINISTIC: no model call, no network, no unbounded work. The one new file
  read is a bounded local `fs.readFileSync` wrapped in try/catch.
- **Fail-open / never crash:** every new branch degrades to *today's exact behaviour* when
  `board/.realizable.json` is missing, malformed, or **stale** (staleness gate included — the
  guardrail explicitly names "stale").
- **No strategy overreach:** the loop only re-picks among options `config` already allows
  (fruit-vs-beans crop, when to divert). It never decides company direction, never invents a
  product, never sells surplus, never touches Beach/Catering/reserves.
- **Rule 6 (never idle a building) preserved:** every guard is a *diversion to another allowed
  crop*, with a guaranteed non-null fallback — the farm grows beans (Mill feed) instead of grapes,
  never nothing.
- Minimal diffs only. Two speculative items from the metric audit are **rejected** (see bottom),
  one dormant defect is **deferred** with rationale.

## Verified facts the change-set depends on

- `board/.realizable.json` top-level keys: `byKind`, `constants`, `generated`
  (`"2026-07-24T03:25:19.659Z"`). `byKind` is string-keyed; each entry has `.verdict`
  (`OVERSUPPLIED` / `RETAIL-OK` / `B2B-DEEP` / `MIRAGE` / …) and `.realizablePerHour_preWage`.
- Grapes (kind 5) verdict = **OVERSUPPLIED**, realizable **~19/h**, against a farm that grows
  ~495/h — the frozen-cash gap.
- Kind IDs align 1:1 between `config.json` and `.realizable.json` (3/4/5 fruit, 7 steak, 8
  sausages, 118 beans, 119 powder). No remap table needed.
- `mill` is in scope at the farm crop-default line (`const mill = state.buildings.find(...)`,
  L737); `pickFarmOrder` returns `{...c}` so `.kind`/`.name` are present.
- No existing `realizable`/`deprioKind`/`loadRealizable` reference in `tick.js`; no `realizable`
  key in `config.json`. Clean insert.

# Change 1 — [GRAPE-SURPLUS LEAK, ~$6,700] Farm diverts OVERSUPPLIED fruit → COFFEE BEANS

**Measured symptom** (`bot.log` 2026-07-24, repeats every 7–12 min):
```
00:30:34 SURPLUS grapes: 2198 units (limit 2000) ≈ $6924 frozen
23:57:02 FARM pick GRAPES x261 (seeds=5971)      <- farm keeps growing them
01:20:06 STORE pick GRAPES x545 @ $6.49 profit=$287/h   <- store drains one batch
```
Root cause: when `seedStock` is fine and the Mill is not bean-hungry, the farm falls through to
`pickFarmOrder(state).name`, whose paper score (`profit × storeRate`) ranks GRAPES #1 on a
`storeRate` (81) that is a fiction under the shared single store lane. `tick.js` references
`.realizable.json` **zero times**, so it cannot see grapes are OVERSUPPLIED (realizable ~19/h). It
grows ~495/h of a good the store rationally buys at ~20/h → ~$3.20/unit frozen, ~2,200 units.

This change makes the farm read the verdict and, when the picked fruit is OVERSUPPLIED/MIRAGE **and
a Mill exists to consume beans**, grow COFFEE BEANS (B2B-DEEP feed → powder, the money line)
instead — the same fruit→beans switch the shelf-full guard already makes ~25 lines below, but keyed
on the realizable verdict so it fires *before* the pile forms rather than reactively after overflow.

## 1A — add fail-open helpers (after `rateFor()`, currently ends L64)

`function` declarations → hoisted, call-order irrelevant. Depend only on `fs`/`path`/`DIR`/`CFG`
(all defined by L19).

```js
// --- realizable-demand guard (board/.realizable.json, written by realizable.js) -----------------
// Classifies each product by how much of its output the market can ACTUALLY absorb (DOCTRINE
// Rule 4d). The fast loop uses it ONLY to divert the farm off an OVERSUPPLIED/MIRAGE crop among the
// options config already allows — never to change strategy. FAIL-OPEN: missing / malformed / STALE
// data => { fresh:false } => every caller keeps its pre-metric behaviour. Deterministic, bounded,
// no model, one local read per tick.
function loadRealizable() {
  try {
    const j = JSON.parse(fs.readFileSync(path.join(DIR, 'board', '.realizable.json'), 'utf8'));
    const ageMs = Date.now() - Date.parse(j.generated || 0);            // NaN if timestamp missing/bad
    const staleMs = ((CFG.realizable || {}).maxAgeHours || 12) * 3600e3;
    if (!j.byKind || !(ageMs < staleMs)) return { byKind: {}, fresh: false };  // absent/old -> fail open
    return { byKind: j.byKind, fresh: true, generated: j.generated };
  } catch (e) { return { byKind: {}, fresh: false }; }                  // absent/corrupt -> fail open
}
// True only when FRESH data marks the kind unsellable-into (OVERSUPPLIED or any MIRAGE*). Unknown
// kinds and stale/missing data -> false, so the loop's behaviour is untouched.
function deprioKind(realizable, kind) {
  if (!realizable || !realizable.fresh) return false;
  const v = realizable.byKind[String(kind)];
  return !!v && (v.verdict === 'OVERSUPPLIED' || String(v.verdict).startsWith('MIRAGE'));
}
```

## 1C — divert OVERSUPPLIED fruit to beans (farm crop default, L766)

Changes **only the caller**, leaving `pickFarmOrder` untouched (the minimal shape from the
decisions audit; `pickFarmOrder` still returns the best fruit by paper score, the caller decides
whether to divert).

**Before:**
```js
      else cropName = pickFarmOrder(state).name;
```
**After:**
```js
      else {
        const pick = pickFarmOrder(state);
        cropName = pick.name;
        // GRAPE-SURPLUS FIX (bot.log 2026-07-24: ~2,200 grapes ≈ $6.7k frozen, refilled every
        // cycle). The picked fruit is OVERSUPPLIED — the shared single store lane absorbs only
        // ~20/h realizable, so growing ~495/h just freezes ~$3.20/unit. When a Mill exists to
        // consume beans, grow COFFEE BEANS instead (B2B-DEEP feed -> powder, RETAIL-OK $1,272/h):
        // the SAME fruit->beans switch the shelf-full guard makes ~25 lines below, keyed on the
        // realizable verdict so it fires BEFORE the pile forms. Gated on a LIVE Mill so a
        // mill-less company still grows retailable fruit (never idle, Rule 6); fail-open on
        // stale/missing data (deprioKind -> false -> keep the fruit pick == today's behaviour).
        if (mill && deprioKind(state.realizable, pick.kind)) {
          log(`FARM ${cropName} OVERSUPPLIED (realizable verdict) — Mill present, growing COFFEE BEANS instead`);
          cropName = 'COFFEE BEANS';
        }
      }
```

**Why gate on live `mill`, not `(mill || millPlanned)`:** a merely-planned Mill with beans already
stocked (so `millHungry` is false) has no grinder yet; diverting fruit to *more* beans would pile
beans with no consumer. If a planned Mill is bean-*hungry*, the `else if (millHungry)` branch above
already routes to beans. Live-Mill gating is the correct, safer condition and matches the current
production state (Mill built; `buildPlan.enabled=false`).

### Before / after behaviour

| condition | before | after |
|---|---|---|
| seeds ok, Mill not hungry, fruit=OVERSUPPLIED, Mill live | GRAPES (~$3.20/unit frozen, ~19/h realizable) | COFFEE BEANS (Mill feed → $1,272/h powder line) |
| grape pile | rebuilds to ~2,200 (~$6.7k frozen) every cycle | drains via store, never re-grown |
| farm idle? | no | no (beans) — Rule 6 held |
| `.realizable.json` missing / corrupt / **stale >12h** | n/a | GRAPES = today's behaviour, no crash |
| no live Mill | n/a | keeps fruit pick (nothing else to grow) |
| store logic | unchanged | **unchanged** |

Downstream is already bean-aware (no other edit needed): `fruitKinds` check skips non-fruit,
`targetUnits` has a `cropName === 'COFFEE BEANS'` branch (L800), `waterPerUnit['COFFEE BEANS']=0.5`
(L756), the order builder handles `'COFFEE BEANS'` (L827–828, qty capped by `seedStock`). The
shelf-full guard (L776–795) becomes a harmless no-op for grapes since the crop is already BEANS
before it runs.

**Risk note:** LOW. Fail-open + staleness-gated + live-Mill-gated. Bean orders remain
water/seed/cash-throttled exactly as today (`inputBudget = 8% of spendable`), so this cannot make
the farm over-buy — it only changes *which* good the throttled output is, and beans are strictly
cheaper to freeze ($0.56 vs $3.20/unit) with a real downstream consumer. **Residual (hand to
strategist, NOT a fast-loop fix):** beans can now accumulate past the Mill's ~180/h appetite; add a
`surplusWatch` entry for coffee-beans (118) and/or a bean-buffer cap so the board is woken if beans
themselves start piling. This is the least-bad busy-work meanwhile.

# Change 3 — [ROBUSTNESS, HIGH] Stuck-detector window is smaller than 2 ticks (L885)

**Measured:** a tick now emits ~22 log lines (verified from `STATE money=` marker gaps of 21/22/23
lines). `slice(-40)` ≈ **1.8 ticks** of history. The detector exists to catch a *persistent*
single-building stall (7-hour water stall, repeated BUY-MISSING, a `SESSION lost` loop), which logs
**one** matching `failSig` per tick — so in a 1.8-tick window `worst[1]` tops out ~2 and never
reaches the `>= 4` escalate threshold. **The strategist is never woken; the loop grinds the failure
forever** — the exact opposite of the "escalate, don't grind" guarantee this block provides, and it
is the backstop for every other fragility below.

**Before:**
```js
    const recent = fs.readFileSync(LOG, 'utf8').trim().split('\n').slice(-40);
```
**After:**
```js
    // Window must cover several TICKS, not several lines: a tick logs ~22 lines and a persistent
    // single-building stall logs ONE failSig/tick, so the old slice(-40) (~1.8 ticks) could never
    // reach the >=4 escalate threshold — the detector was blind to exactly the persistent failure
    // it exists for. ~160 lines ≈ 7 ticks: a once-per-tick failure trips >=4 after ~4 ticks and
    // still ages out below the <2 clear threshold ~7 ticks after recovery. Thresholds unchanged.
    const recent = fs.readFileSync(LOG, 'utf8').trim().split('\n').slice(-160);
```

**Risk note:** LOW. One constant. Larger slice reads a few more KB of an already-rotated log
(run-tick.sh rotates `bot.log` at 5 MB). Threshold constants (`>= 4`, `< 2`) unchanged, so the
clear path still works (ages out ~7 ticks after recovery). Does not spawn more strategists than
intended — the `fastloop-stuck.flag` "once per episode" guard is untouched.

# Change 4 — [ROBUSTNESS, MED] `price-history.jsonl` grows unbounded, read in full every tick (L401–402)

**Measured:** `run-tick.sh` rotates only `$LOG` and `observations.jsonl` at 5 MB;
`price-history.jsonl` is **not** in that set, yet it is appended every tick and then read in full
just to keep the last 36 samples (95 KB / 662 lines after ~2 days). DOCTRINE §5 commits the bot to
running "unattended for weeks" → the file and the per-tick `read + split + JSON.parse` grow without
bound.

**Before:**
```js
      fs.appendFileSync(histFile, JSON.stringify({ t: new Date().toISOString(), p: snap }) + '\n');
      const lines = fs.readFileSync(histFile, 'utf8').trim().split('\n').slice(-((CFG.priceAlert || {}).windowSamples || 36));
```
**After:**
```js
      fs.appendFileSync(histFile, JSON.stringify({ t: new Date().toISOString(), p: snap }) + '\n');
      let all = fs.readFileSync(histFile, 'utf8').trim().split('\n');
      const keep = (CFG.priceAlert || {}).windowSamples || 36;
      // price-history.jsonl is NOT in run-tick.sh's 5MB rotation set but is appended every tick;
      // compact it occasionally to a small multiple of the window so both the file and this read
      // stay bounded over weeks of unattended running. Deterministic, no new rotation policy.
      if (all.length > keep * 4) { all = all.slice(-keep * 4); fs.writeFileSync(histFile, all.join('\n') + '\n'); }
      const lines = all.slice(-keep);
```

`const lines` remains the windowed array, so the downstream `hist = lines.map(...)` is unchanged.

**Risk note:** LOW. The occasional compaction is a whole-file rewrite of ≤ 4×36 lines, cheap and
bounded. If a concurrent writer existed it could race, but this file has a single writer (the tick,
under `.tick.lock`). Alternative one-liner if you prefer no in-tick write: add
`price-history.jsonl` to the `for f in ...` rotation set in `run-tick.sh` L46 — either bounds it.

## REJECTED (speculative / counterproductive — deliberately NOT in the change-set)

1. **Store realizable gate — metric audit DIFF 1 (sink OVERSUPPLIED goods below the sales lane's
   earners).** REJECTED, siding with the decisions auditor. The store runs ONE order and already
   ranks in-stock candidates by the game's own `Profit per hour` probe (Rule 1, ground truth):
   steak (~$334/h) already out-probes grapes (~$287/h), so the existing `storePriority`+$/h sort
   picks the better good whenever both are in stock. Grapes only win the lane when nothing sellable
   beats them — and **selling grapes then is exactly how the frozen pile DRAINS.** Sinking grapes a
   tier below steak/sausages would *slow* the drain of the very $6.7k we are trying to unfreeze, for
   no measured benefit. The store is not why grapes pile; Change 1 (stop *producing* them) is the
   fix. `.realizable.json` is a *production* signal (what to make), not a per-order *sell* signal.

2. **`pickFarmOrder` "prefer absorbable crop" — metric audit DIFF 2.** REJECTED as speculative. Its
   own audit notes it is a **no-op today** (all three fruit are OVERSUPPLIED, so `bestOk` stays null
   and it returns the same fruit). Change 1C already handles the real case at the caller with a
   smaller diff. Adding `bestOk` bookkeeping inside `pickFarmOrder` buys nothing until the day one
   fruit is oversupplied and another is not — revisit then, not now.

## DEFERRED (real but out of fast-loop scope or dormant — flag to strategist/board)

- **[robust #2] `recentEarnRate(buildingId)` ignores its argument** → every building's upgrade
  payback is priced off the STORE's sell rate. **Dormant** (all `upgrades[*].enabled=false`), and a
  correct fix needs per-building tagging of `observations.jsonl` (a schema change, not a minimal
  diff). **Do not enable any queued Farm/Mill L2 upgrade until this is fixed** — flag on the board.
- **[robust #4] `next-due.txt` computed from the pre-order busy snapshot** → at most one extra full
  tick per order-placement round; self-heals next tick. LOW, benign — not worth a diff now.
- **[robust #5] `config.json` lost-update race** (tick serializes a start-of-run in-memory `CFG` on
  the accel-regime / build-success write paths) → near-inert (accel stable ×1 since 2026-07-22;
  `buildPlan.enabled=false`, so neither writer fires). If either write path re-arms, switch it to
  re-read-then-patch-single-field. LATENT — flag, don't fix pre-emptively.
- **[both audits] structural root cause:** three RETAIL-OK finished goods (powder, steak, sausages)
  plus fruit contend for ONE store sales lane. A 2nd retail outlet / dedicated powder outlet, or
  dropping fruit from `farmProducts`, is a **strategist** decision — flagged, not taken.

## Ship / rollback

- Ship order: 1A → 1B → 1C first (the money fix), then 3 (reopen the backstop), then 2 and 4.
- Re-run `node realizable.js` after every `board-data.json` refresh so the verdict stays fresh; the
  12h gate fails the loop **open** (back to today's grape behaviour) if it goes stale — safe, just

  `realizable:` line, and restoring `else cropName = pickFarmOrder(state).name;` — instantly back to
