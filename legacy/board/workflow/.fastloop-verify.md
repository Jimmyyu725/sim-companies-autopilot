## Change 1A — SAFE

Fail-open is genuinely watertight. Traced every degenerate input:
- **file missing / unreadable** → `readFileSync` throws → `catch` → `{fresh:false}`.
- **malformed JSON** → `JSON.parse` throws → `catch`.
- **`byKind` absent** → `!j.byKind` → fail open.
- **`generated` missing** → `Date.parse(0)` → `ageMs` NaN → `!(NaN < staleMs)` = true → fail open.
- **stale > 12h** → `!(ageMs < staleMs)` → fail open.

Confirmed live: top-level keys are exactly `byKind`, `constants`, `generated`; `generated =
2026-07-24T03:25:19.659Z` (age **3.66 h** < 12 h ⇒ **fresh**); grapes(5) verdict OVERSUPPLIED,
`realizablePerHour_preWage = 19`. Helpers are `function` declarations (hoisted); deps
`fs/path/DIR/CFG` all live by L21. No crash path.

## Change 1B — SAFE

## Change 1C — REJECT (as written)

**The change-set diagnosed the wrong pile.** The grape symptom it cites is already being drained
by config changes shipped earlier today, and the real frozen-capital pile is BEANS — which 1C
makes worse.

Live evidence (`bot.log`, `observations.jsonl`, 2026-07-24 02:00):

- The farm is **already** diverting grapes → beans through the existing shelf-full guard:
  `00:30:34 FARM GRAPES shelf full (2198 …) — growing beans instead`, then `01:08:15 FARM pick
  COFFEE BEANS x1796`. No `FARM pick GRAPES` since 23:57.
- The grape surplus **cleared on its own**: `01:20:06 STORE pick GRAPES x545` →
  `01:24:41 SURPLUS cleared`. `fruitBufferHours=8` (set 2026-07-24) caps the grape buffer at
  ~1,088; the 2,198 pile is the *legacy* pile draining, not a re-grown one.
- **Beans (118) on hand = 9,720 units** — ~54 h of Mill feed (Mill draws ~180/h; the L3 farm
  grows beans at ~1,527/h) ≈ **$5–6k of frozen WIP, and climbing**. There is **no `surplusWatch`
  entry for 118** (watch keys are only `5, 7, 119`), so this pile is invisible and wakes nobody.

What 1C actually does:

1. **Moves the problem to a worse place.** It relocates frozen cash from grapes (watched,
   surplus-alert wakes the strategist) to beans (unwatched, already overstocked). Net frozen
   capital does not fall — it grows, silently. For an unattended loop with real cash, replacing a
   *watched* pile with a *silent* one is a regression, not a fix.
2. **Is NOT "the same switch, ~25 lines below, just earlier."** The shelf-full guard fires only
   when the grape shelf already holds its 8 h buffer (`fruitRoom < appleRate`). 1C fires
   **unconditionally** on the verdict — even with an empty grape shelf. Because all three fruit
   are OVERSUPPLIED, with a live Mill + fresh data the farm grows **zero** fruit, ever.
3. **Risks idling the store (Rule 6).** Zeroing the fruit buffer strands the single store queue on
   steak (46 u, ~26/h) + powder (25 u, below the 50 burst) once fruit drains. `IDLE Grocery store
   — nothing in stock to sell` has already occurred **219×** (incl. 4 consecutive ticks
   2026-07-22 09:50–09:56). 1C makes that condition chronic — and Change 3 then escalates it.
4. **Doesn't touch the root cause,** which the change-set itself lists under DEFERRED: the L3 farm
   out-produces *both* the store (~5:1 on fruit) and the Mill (~8:1 on beans). No crop choice fixes
   overproduction; it only chooses which good piles. That is a strategy decision (2nd Mill / 2nd
   outlet / smaller farm orders / sell surplus), not a fast-loop crop swap.

**Recommended action instead of 1C** (ship the *visibility*, not the auto-diversion). Keep 1A/1B/2A
(they surface the verdict, which is genuinely useful and safe). Drop the farm edit. Add the
missing bean watch so the real pile becomes legible and the strategist is woken to fix the
structural cause:

```json

Measured 9,720 u on hand 2026-07-24 (~54h of feed, ~$6k frozen WIP) — the fast loop already diverts oversupplied fruit->beans via the shelf-full guard, so BEANS are the frozen-capital pile, not grapes. Watch so it wakes the strategist; the structural fix (2nd Mill / smaller farm orders / sell surplus) is a strategy call."

If the team insists on a verdict-driven farm diversion, it must (a) preserve the fruit buffer
(only divert once the grape shelf already holds `fruitBufferHours`), and (b) ship the `118` watch
above in the SAME change — never divert into an unwatched sink. Without both, REJECT stands.

## Change 3 — NEEDS-FIX

The widening itself is **correct and needed**: `STATE` markers are ~22 lines apart (measured
21/23/25/20/21/22/23), so `slice(-40)` ≈ 1.8 ticks and a once-per-tick `failSig` can never reach
`>= 4`. **`STUCK` has fired 0 times ever** — the detector is currently dead. `slice(-160)` ≈ 7
ticks reopens it. So far so good.

**But the accompanying spawn is un-throttled, and the risk note is wrong.** `run-strategist.sh`
line 73 does `rm -f … fastloop-stuck.flag …` on **every** exit, so the `if (!already)` guard cannot
dedupe *across* runs — only within one. Once `slice(-160)` makes `worst[1] >= 4` reachable, a
persistent signature does: spawn → strategist exits, deletes flag → next tick `already=false`,
signature still ≥4 → **spawn again**. The stuck path calls `spawn()` **directly**, bypassing
`maybeWakeStrategist`'s 90-min cooldown, so this is a back-to-back max-effort Opus loop on real
API cash — the exact "grind" the design forbids. The note's claims ("once-per-episode guard
untouched", "does not spawn more strategists than intended") are false.

Secondary: the widened window now lets `IDLE Grocery store — nothing in stock to sell` (observed
**219×**, in 4-consecutive-tick clusters) reach the `>=4` threshold — benign/transient store-idle
would now escalate. Change 1C would make this chronic.

Also latent: the stuck block has **no `DRY` guard**, so today a `--dry` tick would `spawn()` a real
strategist. `maybeWakeStrategist` already returns on `DRY`.

**Corrected diff** — keep `slice(-160)`; replace the raw spawn with the throttled, DRY-safe wake:

```js
// Before
      // Wake the reasoning layer once per stuck episode (its own lock dedupes overlaps).
      if (!already) {
        require('child_process').spawn('/srv/appdata/chrome-automation/sim/run-strategist.sh',
          [], { detached: true, stdio: 'ignore' }).unref();
      }
// After
      // Wake the reasoning layer, THROTTLED: run-strategist.sh deletes fastloop-stuck.flag on
      // exit, so `already` cannot dedupe across runs — an unfixable persistent signature would
      // otherwise re-spawn a fresh Opus every tick. maybeWakeStrategist gates on the shared
      // 90-min cooldown and is DRY-safe. The flag (written just above) still carries the URGENT
      // prompt to whichever run wins the wake.
      if (!already) maybeWakeStrategist(`stuck ${worst[0]}`);
```

(`maybeWakeStrategist` already spawns `run-strategist.sh`, logs, and writes `.strategist-wake`.)

## Change 4 — SAFE

Premises verified: `run-tick.sh`'s rotation `for` loop covers only `$LOG` and
`observations.jsonl` — `price-history.jsonl` is genuinely unbounded; single writer under
`.tick.lock` (flock confirmed), so the in-tick rewrite cannot race. `all` is non-empty (the append
precedes the read), `const lines = all.slice(-keep)` keeps the downstream `hist.map` identical.
Whole thing is inside the existing `try/catch`.

Minor nit (non-blocking): once the file exceeds `keep*4` (144) it is rewritten **every** tick
(145→trim→144), not "occasionally" as the comment says. Harmless (~20 KB write/tick under lock);
add hysteresis (`> keep*8`) if you want to avoid it.
