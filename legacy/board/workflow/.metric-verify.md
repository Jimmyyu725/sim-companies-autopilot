## D1 — DEFECT (magnitude): steak capped at 4.33/h, not ~26/h. Verdict right, rate ~6× too low.

Live steak: `S=1.3425`, `dS=−0.00897/day` (draining, correctly RETAIL-OK not OVERSUPPLIED),
retail `unitsSold=35/h`, production `g=48.5/h`, restaurant=0.

The RETAIL branch sets `realizableRate = min(g, headroomFlow)` with
`headroomFlow = max(0, τ(2−S) − k_t·dS)·A_ret/β = (0.12·0.6575 + 5·0.00897)·35 = 0.1237·35 = 4.331/h`.

So the metric credits only a **τ-band 12% marginal sliver** of the all-sellers throughput.
It structurally *cannot* approach the "fully retail-absorbable ~26/h" ground truth even for a
draining, cleanly-clearing lake. Result **$126** vs measured **~$324** (2.6× low) and vs the
task's "cap at ~26/h" (rate 6× low). The spec's §7.1 admits this ("elasticity-limited marginal
add… deliberately conservative"), but by the task's own named check it is a miss.

**Minimal fix (verified against live data):** for a *clearing* retail lake, credit the marginal
building a real share of the demand it displaces, not a τ-sliver:
```
m(S)      = clamp(1 − S/2, 0, 1)            # the price/sell-through multiplier the spec already uses
rr_retail = min(g, m(S) · A_ret)           # (keep τ-band as an *extra* additive headroom if desired)
```
Live check of this fix (nothing else changed):
- **steak**: m=0.329 · 35 = **11.5/h → ~$335** ≈ measured $324 ✅ (was 4.33/h/$126)
- **construction**: m=0.451 · 120 = **54/h → ~$446** — strengthens the "high-volume" signal ✅
- **apples**: m=0.253 · 110 = 27.8/h → ~$20 — still lowest, verdict **OVERSUPPLIED unchanged**
  (verdict is set by S/dS, not rr) ✅ no regression.
The fix repairs the one failed named check without breaking any passing case.

## Collateral findings (outside the required 7, flagged for honesty)

**C1 — Recipe-graph blind spot → false MIRAGE on construction/research goods.**
Goods consumed by **game mechanics** (building construction, research) rather than by another
resource's recipe are invisible to the Leontief propagation and get `der=0 → MIRAGE`:
`construction-units (k111)`, `steel-beams (k107, g=283/h)`, `bulldozer (k112)`,
`robots (k114)`, `materials-research (k113)`, `recipes (k145)`. steel-beams IS consumed
(by construction-units) but inherits der=0 because construction-units itself terminates in a
mechanic the graph can't see. Every building expansion really consumes these — the metric would
tell the board "never build steel-beams." None are in the known-truth set, so no required case
fails, but this is a real **false-negative class**. Fix: seed a construction/research demand
leaf, or don't hard-MIRAGE an `isExchangeTradable` good whose only consumers are
construction-units / `isResearch`.

**C2 — Every B2B dollar figure rests on an ASSUMED price-keep, not a real order book.**
`orderBooks` covers only kinds 2,3,4,5,66,111,119. All four B2B winners fall to the §4.2
fallback `priceKeepExch = isUp ? 0.6 : 0.5` (a coin-flip, `bookStale:true`):
crude $757 (pk 0.5), dough $1006 (pk 0.6), carbon-fiber $95 (pk 0.6), combustion $257 (pk 0.6).
Flip crude's pk 0.5→0.25 and its $/h halves. **Verdicts firm; every B2B $ magnitude is ±2×
and assumption-laden.** (Already flagged in §8.1 — confirmed load-bearing.) Probe real sell-book
depth for kinds 10/137/75/52 before any large B2B capex.

**C3 — Reported `A(total)` for raw goods is astronomically large and not literal.**
water 15.7M, apples 1.6M/h (apples→apple-cider ×8, cider A≈199k). Harmless — the B2B rate is
capped `min(g, α·A_der)` so rr = production-limited g when demand explodes — but the "A(total)"
column should not be read as real units/h. Classification is unaffected.

## Verdict

The metric **passes the three critical separations** (crude/dough/carbon alive vs aerospace dead;
samosa king HIGH; apples OVERSUPPLIED) and is internally honest (§7 reproduces exactly). It **fails
one named check — steak's realizable rate (4.33/h vs ~26/h, $126 vs ~$324)** — fixable with the
one-line D1 change. On **k52 it diverges from the task's ground-truth but is vindicated by live
proof** (three clearing vehicle lakes). Two collateral defects (C1 construction/research blind
spot, C2 assumed B2B price-keep) do not touch the required cases but should be logged before the
board uses this to gate capex.
