## 1. scan-rooms.js status: RUNS, but room attribution is UNRELIABLE

- Room subscriptions are intact (no `ROOM LINK NOT FOUND`; the 2026-07-22 wipe has not recurred).
  All five sidebar links exist and unread badges still append digits to the link text
  ("Game 1", "Sales 108"), confirming the startsWith matching rationale.
- BUG (reproduced twice, back-to-back runs): adjacent rooms return identical or lagged tails.
  Run 1: Game == Help == Sales byte-identical. Run 2: Help == Sales identical, and the text
  captured under "Aerospace sales" was actually the HELP room's conversation (verified by direct

  (e.g. "answer questions seen in Help"). Aggregate reading is still fine.

  `href="/messages/chatroom_<Name>/"`. After any click, VERIFY `location.href` contains the

  ~1.7–2.8 k chars, so a `slice(-2600)` on a fresh direct load can bleed into sidebar text —
  anchor reads on the CAPS room header instead.

## 3. Message composer DOM (what posting needs — inspected only, NOT exercised)

- Input: exactly ONE visible `<textarea placeholder="Type here, use @ or : for suggestions"
  autocomplete="off">` — no id, no name, no class, no maxlength attribute, and NOT inside a
  `<form>`. Unique selector: `textarea[placeholder^="Type here"]`. It sits in
  `div.input-group`, absolutely positioned over a mirror div.
- Send button: sibling `span.input-group-btn > button[type=button].css-15ic6os` containing
  `svg[data-icon="paper-plane"]`. No aria-label, no title, empty innerText — identify it ONLY
  via the svg `data-icon="paper-plane"`, and require exactly one match or refuse.
- React quirks (both already proven elsewhere in this repo):
  - Set the text with the injected `setInput()` helper (prototype value setter + input/change
    events); a bare `.value =` will be ignored by the controlled component.
  - Clicking MUST be a native `button.click()` — `dispatchEvent(new MouseEvent(...))` does NOT
    fire the React handler (scan-rooms.js header note; same lesson as scrap.js confirm).
- `@` and `:` in the text open mention/emoji suggestion popups — a poster should avoid leading
  triggers or handle/dismiss the popup before clicking send.
- Enter-key behavior is UNTESTED (deliberately — nothing was typed); treat paper-plane click as
  the only known send path.
- One-time rules overlay: after (re)subscribing to a room, a per-room overlay appears once;
  dismiss via the visible "Ok, and do not show again" button before reading/posting.

## 4. Spec for a future self-gating post primitive (NOT built yet — do not build without owner OK)

Pattern: pages/scrap.js / pages/bonds-adjust.js. `window.__chatpost = { room, text, confirm }`.
- Without `confirm:true`: dry run — verify `location.href` matches `chatroom_<room>`, locate the
  textarea and the unique paper-plane button, return `{dry:true, room, wouldPost:text}` WITHOUT
  touching the textarea or the button.
- With `confirm:true`: `setInput(textarea, text)` → short sleep → native click on the single
  paper-plane button → sleep → verify our company name + the text tail now appear at the pane
  bottom, return that evidence.
- REFUSE (return, never guess) if: URL is not the requested room; visible textarea count != 1;
  paper-plane button count != 1; text is empty or > ~300 chars; text starts with `@` or `:`.
- Run goto+post inside ONE flock (`flock ... sh -c 'node cdp.js goto <room-url> && node cdp.js
  js pages/chat-post.js'`), LESSONS B5.
